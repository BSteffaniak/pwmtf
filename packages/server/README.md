# PWMTF server

This package owns authoritative command authorization, revision/idempotency enforcement, durable acceptance, scheduling, recovery, identity, social/lobby/rematch persistence, and native HTTP/OIDC/secure-WebSocket operations. Canonical gameplay decisions remain in `pwmtf_billiards` and `pwmtf_eight_ball`; this package authenticates and durably orchestrates them. A rejected WebSocket command receives a typed `Rejected { reason }` followed by the current complete authoritative state, allowing the client to roll back prediction without dropping a healthy connection.

## Session socket (`GET /ws`, session version 2)

One binary WebSocket per tab serves every match and lobby of the account. Origin and session cookie are checked before the upgrade (401 when unauthenticated). The first frame must be `Hello` within 10 s; the server replies `Welcome` with the negotiated version or closes. Text frames, malformed or oversize frames (> 512 bytes), a second `Hello`, and connections silent for more than 45 s are closed. Wire formats live in `pwmtf_protocol::session`.

- **Matches.** `SubscribeMatch` is authorized from durable participants (else `SubscriptionDenied`) and answered with the complete `MatchState` (`last_command` absent). Up to 16 matches per connection. A `Command` requires a subscription on that connection (else `Rejected { NotSubscribed }`). It is durably committed before any send, then every subscriber receives `MatchState` with `last_command` (command id, actor, command, `playback_ticks`) describing the `revision - 1 → revision` transition, so observers can replay the shot bit-exactly. An identical retransmit of an accepted command is answered with the current state only. Other refusals send `Rejected { reason }` plus a fresh `MatchState` to the sender only. Authoritative timeouts are broadcast the same way with a `Timeout` transition. `Timeout` is server-only: a client-sent `Timeout` is refused as `IllegalMove`, and a client command id inside the reserved synthetic-timeout namespace (`timeout_command_id`) is refused as `Malformed`, so no client can end a turn or pre-empt a future timeout's idempotency key.
- **Deadlines.** The next turn starts after the accepted shot's authoritative playback: `due_at = now + playback_millis(physics, playback_ticks) + turn_duration`. Placement, timeout, and concession have zero playback. The deadline is journaled with the command, so recovery is exact and each timeout applies once.
- **Previews.** A single helper checks that the sender holds the active seat of an in-progress match at the preview revision, before the deadline, with a 40 ms rate limit (a cancel after a non-cancel is exempt) and a monotonic sequence. Valid previews go only to the other participant's subscribed connections.
- **Lobbies.** Lobby presence is a live connection with an active `SubscribeLobby` and is held in memory only. Each presence has a fresh identity, and durable explicit readiness (`POST /api/lobbies/{id}/ready`, which returns 409 without presence) is recorded per presence identity. A participant loses readiness when their last ready presence disappears, including on a process restart, which clears all readiness rows. A match starts atomically only while both participants are present and ready; this is checked on ready and on subscribe. A failed start attempt during subscribe is logged and retried later; it never drops the new presence. `GET /api/lobbies/{id}` reports `self_present`, `self_ready`, `opponent_present`, and `opponent_ready` without exposing participant identifiers.
- **Pushes.** The connection registry pushes `SocialChanged` to every connection of each affected account when a challenge is created or accepted, an invitation is redeemed, a lobby is cancelled or started, or a rematch is offered or accepted. Lobby members receive `LobbyChanged` and `MatchStarted`. An accepted rematch sends `MatchStarted { lobby_id: 0 }`. Clients refetch over HTTP on these hints.

## Concurrency

Each loaded match is an independent unit with its own async authority mutex, broadcast channel, cached head (revision, active seat, deadline), and preview gate. No lock shared across matches is held across a database await; the registries are synchronous maps used only for lookups. The scheduler sweep applies due deadlines of different matches concurrently, each under its own unit lock. Each socket has one bounded outbound queue, and a slow consumer whose queue fills is disconnected and resynchronizes on reconnect.

This package also exposes an explicitly insecure, compile-time-gated localhost
adapter for manual two-browser testing. `--features insecure` and
`PWMTF_DEV_MODE=true` must agree exactly; the configured origin must be loopback
HTTP and Google credentials must be absent. Username-only login creates the same
hash-only durable sessions and stable handles used by normal product flows, but
never creates or impersonates a Google identity. Production builds do not contain
the development route.

`./scripts/test-native-deployment-smoke.sh` qualifies the native boundary with independently authenticated WebSocket participants, measured base delay, deterministic jitter, first-transmission loss/retransmission, duplicate/noise delivery, intermediate reconnect, terminal concession convergence under the same impairment model, terminal reconnect for both participants, exact durable command counts, deadline removal, process restart, and application-consistent backup/restore. It speaks session version 2 over `/ws` and checks per-seat `MatchState` seat/revision/completion/deadline values before and after terminal convergence and restart. `cargo run -p pwmtf_server --example seed_native_smoke -- <db>` also prints ready-to-send hex session frames (`hello_frame`, `*_subscribe_frame`, `live_command_frame`, `live_terminal_command_frame`).

`cargo nextest run -p pwmtf_server --test session_socket` runs a real loopback server against raw WebSocket clients. It covers the handshake, subscription authorization, shot broadcast with `last_command`/`playback_ticks`, observer replay converging to the server checksum, exactly-once duplicate retransmit after reconnect, rejection reasons, refusal of client-sent timeouts and reserved timeout ids, lobby presence plus ready leading to `MatchStarted`, opponent-only preview routing, and a deadline offset that includes playback time.
